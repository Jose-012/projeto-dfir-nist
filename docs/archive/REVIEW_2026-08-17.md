# Revisão histórica — 2026-08-17 / baseline v6.4.0 (arquivada)

A revisão final consolidou o projeto em três classes de componentes:

1. Production Runtime — Rust + assets estáticos;
2. Build Toolchain — Rust/Cargo + Deno;
3. Engineering/QA Tooling — CPython + Shell.

## Decisões confirmadas

- backend confiável continua Rust;
- `dfir-engine` permanece processo separado e processo separadoado;
- SQLite + SQLx e repositories finos continuam sem ORM;
- HTML server-rendered é a base do frontend;
- TypeScript é compilado para browser;
- Fase 0 não distribui HTMX, Alpine.js ou Pico.css;
- Deno não entra no runtime;
- CPython/Shell não entram no runtime;
- HTTP/JSON é o transporte de dados do browser;
- SSE é opcional para eventos unidirecionais de jobs;
- WebSocket não entra no MVP;
- timeline Fase 0 não exige biblioteca de terceiros;
- `vis-timeline`/D3 só podem entrar mediante necessidade demonstrada.

## Prevenções incorporadas

- fronteiras de runtime explicitadas;
- imagem de produção sem runtimes alternativos;
- documentação de toolchain separada da documentação de runtime;
- artefatos frontend versionados para build offline;
- validator verifica ausência de runtimes alternativos no container;
- validator verifica existência/coerência dos assets frontend;
- release gate exige Deno/Python executados e registrados, sem confundir manifestos com evidência.

## Limitação deste ambiente

Não há Cargo, Deno ou Podman disponíveis neste ambiente de preparação. O compilador TypeScript disponível foi usado apenas como verificação suplementar do código de browser; isso não substitui o gate oficial com Deno. Compilação Rust, transpile oficial Deno, runtime, processo separado e supply-chain continuam pendentes até execução em Linux/WSL2 preparado.
