Antes
-----
`list_recommendations` só comparava a string quando havia filtro, e
`export_incident_findings` colocava tudo que não fosse exatamente `IMMEDIATE`
na partição estratégica. Categoria desconhecida, ausente ou não textual podia
sumir do filtro ou ser reclassificada.

Regressão antes da correção:
`cargo nextest run --locked -p dfir-app malformed_stored_recommendation_categories`
Resultado: exit 100, como prova do defeito. Para categoria `URGENT`:
- listagem sem filtro: Ok(1);
- listagem filtrada por IMMEDIATE: Ok(0);
- exportação: Ok(immediate=0, strategic=1).

As linhas vigentes foram inseridas por SQL em banco descartável sem remover ou
alterar triggers append-only. O mesmo teste cobre categoria ausente e número no
lugar de string.

Depois
------
`stored_recommendation_category` exige `IMMEDIATE` ou `STRATEGIC` em toda
recomendação vigente antes de listar ou exportar. Dado inválido retorna
`AppError::Config` com o ID da recomendação e o campo `category`; não há partição
default nem reparo silencioso de histórico antigo. O schema e os dados válidos não
mudaram.

Comando focado: `cargo nextest run --locked -p dfir-app recommendation`
Resultado: 24/24 testes passaram, incluindo os três casos inválidos, filtros e
partição de exportação com uma recomendação válida de cada categoria.
